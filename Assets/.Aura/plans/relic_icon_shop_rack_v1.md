# Relic Icon, Base-vs-Hovered Numbers, and the Shop Rack

## Objective
Replace the shop's text relic rows with square 1:1 relic icons on a straight rack whose hover opens a tooltip, and make relics and cards show printed base numbers at rest and final stat-scaled numbers on hover.

## Changes
- 'Assets/Scripts/Items/RelicDefinition.cs' - add `RelicScaling.Resolve(int statTotal)`; add `EffectFormula(ItemInstance)` (resting) and an `extraStat` overload of `EffectSummary` (hovered)
- 'Assets/Scripts/Cards/CardData.cs' - add a `BuildDescription` overload that prints a supplied value instead of one it calculates
- 'Assets/Scripts/UI/IHoverView.cs' - (create) one-method interface so the hover lift drives a card or a relic icon
- 'Assets/Scripts/Combat/CardHoverEffect.cs' - drive `IHoverView` instead of a hard `CardView` reference
- 'Assets/Scripts/Combat/CardView.cs' - implement `IHoverView`; render the printed base at rest and the stat-scaled value on hover
- 'Assets/Scripts/UI/CardTooltip.cs' - add a `Show(title, body, source, Component owner)` entry point so one tooltip serves cards and relics
- 'Assets/Scripts/UI/RelicText.cs' - (create) the resting caption and the hovered tooltip body for a relic
- 'Assets/Scripts/UI/RelicIconView.cs' - (create) one square relic icon: body, caption, price, buy click, hover
- 'Assets/Scripts/UI/RelicRack.cs' - (create) the straight rack that parts neighbours and bends the hovered icon left
- 'Assets/Scripts/UI/ShopPanel.cs' - `relicRows` becomes `RelicIconView[]`; add `FillRelicRack` and `Buy(RelicIconView)`
- 'Assets/Editor/CardGameSceneBuilder.cs' - add `BuildRelicIconPrefab`, `MakeShopRelicSlot`, `MakeRelicRackRow`; narrow both bottom racks; wire the new prefab into `BuildRoomScene`
- 'Assets/Prefabs/RelicIcon.prefab' - (create, by the builder) the icon prefab
- 'Assets/Scenes/Room.unity' - regenerated by the builder; not hand-edited

## Relevant Assets and Quirks
- **What "base" means.** A relic at rest shows its *formula* with its own stats folded into the flat number: Loaded Dice (`baseValue 20`, `perStatPoint 1`, guaranteed `agility 1`) reads `(21 + AGI)%`; with a roll of +2 Agility it reads `(23 + AGI)%`. Hovered, the tooltip shows only the resolved total, as if the relic were owned: `42% chance of an extra card`. A card at rest shows its printed `baseValue`; hovered, its stat-scaled value.
- **Double-counting guard.** `Inventory.GetBonuses` already folds a carried relic's own stats into `PlayerStats`, so the "add this relic's own stats" figure is only for a relic that is **not owned yet** — the shop rack. `EffectSummary(stats)` keeps its current meaning (defaulted `extraStat = 0`) for the bag and sell views; only the rack passes a value.
- **Per-stat label**: use the existing `RelicInstance.StatLabel` (`STR`/`AGI`/`INT`/`VIT`/`WIL`) rather than inventing "dex", so the formula matches the bag rows.
- **A relic with `RelicEffect.None`** has no formula to show. Its resting caption is its compact stat line and its hovered tooltip shows the same stats plus tier and description.
- **Cards with `valueSource != Fixed`** (`PerCardInHand`, `PerCardPlayed`, `EmptyHand`) have no printed base — `baseValue` is the per-card amount, and resolving with no context yields 0. They keep their live read in both states. This is the single carve-out to the rest/hover split.
- **Rack layout**: `RelicRack` currently spans panel-x −960…−20 and `EquipmentRack` +20…+960, so a 430-wide tooltip beside an icon would land on the equipment rack. Both racks must be narrowed to open a centre gutter wider than the tooltip plus its `gap` (16) and `screenPadding` (12).
- **Hover rules that must not be broken**: no `Canvas` with `overrideSorting` on an icon (it sorted cards behind the deck view at orders 100 and 200); no sibling reordering on hover (layout reflow slid the card out from under the pointer and caused jitter). Lift stays scale-only; the rack writes `anchoredPosition`/`localRotation` directly; the tooltip stays a single shared instance on its own order-500 canvas with every graphic's `raycastTarget` off.
- **Tooltip is straight by construction**: it is its own canvas object, so the icon's leftward bend cannot rotate it.
- **`CardTooltip.Owner` is today a `CardView`** and `CardView.OnDestroy` hides the tooltip when it still owns it; widening `Owner` to `Component` keeps that guard working for both types.
- **`ShopEntryView` keeps serving the equipment rack.** `BindCard` becomes unused but is left in place; removing it is not part of this change.
- **`CardGameSceneBuilder` is the single source of truth**: the icon prefab, the rack layout and `ShopPanel`'s references must all be authored there, or the next `Build Game Scenes` run reverts them.
- **The editor was in play mode** on `Assets/Scenes/Room.unity` at last check. `BuildGameScenes()` calls `EditorSceneManager.SaveOpenScenes()` and then `NewScene(..., NewSceneMode.Single)`, so play mode must be stopped before the rebuild step.
