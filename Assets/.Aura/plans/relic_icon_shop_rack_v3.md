# Relic Icon, Inspect Scrim, and the Shop Rack

## Objective
Replace the shop's text relic rows with square 1:1 relic icons on a straight rack — price at rest, name and a full tooltip on hover with the rest of the scene darkened — and make cards show their printed base at rest and their stat-scaled number on hover.

## Changes
- 'Assets/Scripts/Items/RelicDefinition.cs' - add `RelicScaling.Resolve(PlayerStats stats, int extraStat)` and an `extraStat` parameter on `RelicDefinition.EffectSummary`
- 'Assets/Scripts/Cards/CardData.cs' - add a `BuildDescription` overload that prints a supplied value instead of one it calculates
- 'Assets/Scripts/UI/IHoverView.cs' - (create) one-method interface so the hover lift drives a card or a relic icon
- 'Assets/Scripts/Combat/CardHoverEffect.cs' - drive and cache an `IHoverView` instead of a hard `CardView` reference
- 'Assets/Scripts/Combat/CardView.cs' - implement `IHoverView`; print the base at rest and the stat-scaled value on hover
- 'Assets/Scripts/UI/CardTooltip.cs' - add a `Show(title, body, source, Component owner)` entry point so one tooltip serves cards and relics; widen `Owner` to `Component`
- 'Assets/Scripts/UI/RelicText.cs' - (create) the tooltip title and body for a relic: tier, effect, stat lines
- 'Assets/Scripts/UI/RelicIconView.cs' - (create) one square relic icon: body, one caption slot, canvas group, buy click, hover
- 'Assets/Scripts/UI/RelicRack.cs' - (create) the straight rack: lift, spread, leftward bend, neighbour dim, and the inspect scrim's fade
- 'Assets/Scripts/UI/ShopPanel.cs' - `relicRows` becomes `RelicIconView[]`; add `FillRelicRack`, a `Buy(RelicIconView)` overload and a scrim reference
- 'Assets/Editor/CardGameSceneBuilder.cs' - add `BuildRelicIconPrefab`, `MakeShopRelicSlot`, `MakeShopRelicRow`, the shop scrim `Image`, and swap the relic rows in `BuildRoomScene`
- 'Assets/Prefabs/RelicIcon.prefab' - (create, by the builder) the icon prefab
- 'Assets/Scenes/Room.unity' - regenerated by the builder; not hand-edited

## Relevant Assets and Quirks
- **The icon at rest shows nothing but its price.** The caption under the body is the price while at rest and is swapped for the relic's name on hover, in the same slot and the same text object. The body is a flat placeholder square with no text: a sprite replaces it later, and neither `ItemData` nor `RelicDefinition` has an `art` field today, so nothing is authored.
- **No base scaling string anywhere.** `EffectFormula` is deliberately not written. The tooltip body is the effect line only (carrying the final resolved number), then one `StatLines()` row per stat including zeros. The small scaling arrow you want at the end of the description is deferred to a later change and is not built here.
- **Tooltip title carries the tier** (`name  [TIER II]`) because the row being replaced shows it today, and dropping it would lose information rather than move it. `RelicInstance.TierLabel` and `StatLabel` are the existing labels.
- **The final number is "as if it entered your deck".** A rack relic is not in `Inventory`, so `PlayerStats` does not contain it: the tooltip passes `extraStat = instance.GetStat(definition.scaling.stat)`, which `Resolve` folds in as `(stats.GetStat(stat) + extraStat) * perStatPoint` before the divisor and the percent clamp. Loaded Dice at 20 player Agility with +2 rolled reads `42%` rather than `40%`.
- **Double-counting guard.** An owned relic's stats are already inside `PlayerStats` via `Inventory.GetBonuses`, so `RelicEffects.SumPercent` and `EffectSummary(stats)` keep calling the one-argument `Resolve`, which defaults `extraStat` to 0. Only the shop rack passes a value.
- **A relic with `RelicEffect.None`** has no effect line; its tooltip is the stat lines plus the description.
- **Cards with `valueSource != Fixed`** (`PerCardInHand`, `PerCardPlayed`, `EmptyHand`) have no printed base — `baseValue` is the per-card amount and resolving with no context yields 0. They keep their live read in both states. This is the single carve-out to the rest/hover split for cards.
- **Draw order is hierarchy order, and `MakeCanvas()` sets no `sortingOrder`** (verified: the room's UI is all on an order-0 canvas, the deck view and character menu on `MakeOverlayCanvas` at 100/200, the tooltip at 500). So the scrim needs **no canvas of its own** and cannot out-sort the character menu: it is an `Image` inside the full-screen shop panel, and it must be drawn after `EquipmentRack` to darken the exact region the tooltip overlaps.
- **Consequence of that placement**: the scrim also darkens the relic rack, so the focused icon does not escape it. Focus comes from geometry (bigger, parted, bent) plus the neighbours' `CanvasGroup` dim, and the tooltip is fully bright above it. The panel's sell hint and leave button sit before the scrim, so they stay lit.
- **The scrim must have `raycastTarget = false`.** Raycasting ignores draw order, so a clickable scrim anywhere under the pointer would swallow the hover it was opened for.
- **Hover rules that must not be broken**: no `Canvas` with `overrideSorting` on an icon (it sorted cards behind the deck view at orders 100 and 200); no sibling reordering on hover (layout reflow slid the card out from under the pointer and caused jitter). Lift stays scale-only plus direct writes to `anchoredPosition`/`localRotation`; the tooltip stays a single shared instance on its own order-500 canvas with every graphic's `raycastTarget` off; the neighbour `CanvasGroup` keeps `blocksRaycasts = true` so a dimmed relic is still hoverable and buyable.
- **The tooltip is straight by construction** — its own canvas object — so the icon's leftward bend cannot rotate it. Its existing screen clamping is left unchanged; the scrim is what makes the overlap readable.
- **`CardTooltip.Owner` is a `CardView` today** and `CardView.OnDestroy` hides the tooltip when it still owns it; widening `Owner` to `Component` keeps that guard working for both types.
- **`ShopEntryView` keeps serving the equipment rack.** `BindCard` becomes unused but is left in place; the shop's equipment rack is not part of this change.
- **`CardGameSceneBuilder` is the single source of truth**: the icon prefab, the scrim, the rack layout and `ShopPanel`'s references must all be authored there, or the next `Build Game Scenes` run reverts them.
- **The editor was in play mode** on `Assets/Scenes/Room.unity` at last check. `BuildGameScenes()` calls `EditorSceneManager.SaveOpenScenes()` then `NewScene(..., NewSceneMode.Single)`, so play mode must be stopped before the rebuild step.

## Execution notes

Two places were built differently from the steps as written, both deliberately:

- **The relic row has no `HorizontalLayoutGroup`** (step 5 asked for one). A layout group writes the same
  `anchoredPosition` the rack owns, which is exactly the fight that made the combat hand jitter. The row is
  a plain `RectTransform` with a `LayoutElement` for its height, and `RelicRack` is the only owner of icon
  positions — the same division of labour as `HandFan`.
- **The scrim is drawn after `EquipmentRack` and before `RelicRack`**, not as the panel's literal last child
  as step 5 said. Draw order inside the panel is hierarchy order, so "last child" would have darkened the
  relic rack itself along with everything else. Where it is now, the shop recedes and the rack stays lit,
  which is what being in focus has to mean.

Verified on the rebuilt scene: `ShopPanel` children are ordered title, gold, notice, CardRack,
EquipmentRack, hint, leave, **ShopScrim**, **RelicRack**; the three icons are 104x104 squares at x = -150, 0,
+150 with `AspectRatioFitter` aspect 1, `hoverScale` 1.24, the shared `CardTooltip` prefab bound, and no
`Canvas` of their own.

Step 1 checked numerically against the live database: Loaded Dice at 20 player Agility reads
`Loaded Dice: 40% chance of an extra card` owned and `43%` on the rack, a delta of 3 = its own 3 points of
Agility x `perStatPoint` 1.
